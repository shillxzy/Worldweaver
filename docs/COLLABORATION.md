# Спільна робота над книгою

## Що є «проєктом»

Спільний доступ надається до **світу** разом з усім, що в ньому є: книгами, розділами, енциклопедією, персонажами, фракціями, хронологією, графами та щоденником.

Поділитися окремою книгою не можна свідомо. Книги одного світу спираються на ту саму енциклопедію. Доступ лише до книги або розкрив би дані світу через персонажів і посилання, або розірвав би зв'язки між рукописом і лором.

У бібліотеці спільні книги позначено «Спільна · {власник} · {роль}». Сам доступ налаштовується кнопкою «Доступ» у боковій панелі проєкту.

## Ролі

Ролі впорядковані: кожна наступна містить усі права попередніх.

| Роль | Читати | Коментувати | Змінювати вміст | Учасники й запрошення | Видаляти книги | Публічний доступ, передача власності, видалення світу |
|---|---|---|---|---|---|---|
| Читач (`viewer`) | ✓ | | | | | |
| Коментатор (`commenter`) | ✓ | ✓ | | | | |
| Редактор (`editor`) | ✓ | ✓ | ✓ | | | |
| Адміністратор (`admin`) | ✓ | ✓ | ✓ | ✓¹ | ✓ | |
| Власник (`owner`) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

¹ Адміністратор керує редакторами, коментаторами й читачами. Призначати й знімати адміністраторів може лише власник.

**Зміна вмісту** охоплює:
- розділи та їхній порядок;
- імпорт DOCX;
- сторінки та властивості;
- персонажів, фракції, зв'язки, події хронології;
- розкладку графів;
- щоденник;
- запуск перевірок і рішення щодо знахідок.

**Робочі інструменти команди** (потрібна роль від редактора):
- історія версій розділу;
- експорт DOCX;
- перевірки та AI-пояснення.

Читач і коментатор бачать рукопис у режимі читання, без редактора.

**Власник** завжди один: це `World.owner`. Він не може покинути проєкт, доки не передасть власність іншому учаснику. Після передачі колишній власник лишається адміністратором.

Персональні речі нікому не передаються: налаштування, словник правопису, власні шаблони сторінок і власні запуски аналізу.

## Як перевіряються права (сервер)

Уся логіка зосереджена в `apps/common/scoping.py`.

- `accessible_worlds(user, min_role)` повертає світи, де користувач є власником або учасником з потрібною роллю. На ньому побудовано всі запити книг, розділів, дошок і знахідок.
- `world_or_404(user, id, min_role)` та `require_role(...)` повертають **404**, якщо доступу до світу немає зовсім (так id чужих світів не розкриваються), і **403**, якщо роль замала.
- `WorldScopedMixin` для вкладених ресурсів (`/worlds/{id}/…`) перевіряє роль ще до обробки запиту. За замовчуванням читання потребує `VIEW`, а будь-яка зміна — `EDIT`. Окремі дії задано в `action_roles`, наприклад видалення книги потребує `MANAGE`.
- Відповіді містять `my_role` (у книгах і світах), щоб інтерфейс міг сховати недоступне. Проте вирішує завжди сервер.

Інтерфейс отримує роль через `AccessContext` (`src/access.ts`). Хуком `useAccess()` компоненти ховають кнопки створення й видалення, вимикають поля та показують текст через `DocView` замість редактора.

## Запрошення

- **Особисте (email).** Призначене одній адресі й одноразове, діє 30 днів. Чекає в бібліотеці запрошеної людини після входу з цією адресою (блок «Запрошення для вас»), де його можна прийняти або відхилити. Застосунок працює локально й не надсилає листів, тому посилання на запрошення можна передати вручну.
- **Посилання.** Має роль (читач, коментатор або редактор, але ніколи адміністратор, бо посилання можна переслати далі), термін дії (1/7/30 днів або без терміну) і ліміт використань. Відкликається будь-коли.
- Відкриття `#/join/{token}` показує світ, книги, автора запрошення та роль. Якщо людина не увійшла, спершу відкривається форма входу, а після входу — та сама сторінка запрошення.
- Прийняття ніколи не знижує вже наявну роль.

## Коментарі

- Коментарі можна залишати до розділів і до сторінок енциклопедії. Кнопка «Коментарі» відкриває бічну панель.
- Якщо перед коментуванням виділити фрагмент тексту, він збережеться як цитата.
- Обговорення мають відповіді одного рівня. Закрити обговорення може його автор або будь-хто з роллю від редактора.
- Редагувати можна лише свої коментарі. Видаляти — свої, а адміністратори й власник — будь-які.
- Коментарі ніколи не змінюють текст. У списку розділів видно кількість відкритих обговорень (💬).

## Публічний сайт

- Вимкнений за замовчуванням. Вмикає його лише власник, у вкладці «Публічний доступ».
- **Нічого не відкривається автоматично.** Власник окремо позначає книги, розділи («усі» / «лише готові» / «жодного» або по одному) і сторінки енциклопедії.
- Сайт доступний за адресою `#/s/{token}` без акаунта й без сесії. Він лише для читання і має обмеження частоти запитів (`public: 120/min`).
- Посилання на непублічні сторінки перетворюються на звичайний текст. Властивості типу «сторінка» не показують прихованих сторінок, а приховані id повертають 404.
- Кнопка «Нове посилання» одразу вимикає старе. Вимкнення сайту ховає все.

## Хто що змінив

- Розділи та сторінки зберігають `updated_by`, тож видно, хто вносив останні зміни.
- Версії розділу зберігають автора збереженого тексту.
- Одночасне редагування захищене ревізіями. Якщо двоє змінили одне й те саме, друге збереження отримує 409 і пропозицію порівняти версії.

## Що свідомо відкладено

- Пропозиції змін у режимі рецензування (track changes) для коментаторів.
- Спільне редагування в реальному часі з курсорами інших людей. Зараз працює оптимістичне блокування з ревізіями.
- Надсилання листів із запрошеннями: для цього потрібен поштовий сервер.
- Журнал активності проєкту.
