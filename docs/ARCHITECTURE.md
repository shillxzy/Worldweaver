# Архітектура Worldweaver

```
Browser (React + Tiptap) ──/api/v1 (session cookie + CSRF)──▶ Django REST API ──▶ PostgreSQL
        ▲  Vite dev proxy                                         │      ▲
        │                                                         │      │ AnalysisJob (черга в БД)
        └──────────── polling статусу завдань ◀───────────────────┘      │
                                                         manage.py run_worker ──▶ AIService ──▶ GeminiBackend ──▶ Google Gemini API
```

## Backend (`Backend/`)

| Застосунок | Відповідальність |
|---|---|
| `apps.common` | Єдиний формат помилок, пагінація, ізоляція даних (`WorldScopedMixin`, `WorldRelatedField`, `parse_id`), Unicode-`LIKE` для SQLite |
| `apps.accounts` | Реєстрація, вхід/вихід, профіль, налаштування (`Profile`), зміна пароля, видалення акаунта |
| `apps.worlds` | `World`, `Tag`, `LoreEntry`, `Character`, `Faction`, `FactionMembership`, `TimelineEvent`, `EventParticipant`, `TimelineDependency`, `Relationship`; пошук у світі |
| `apps.books` | `Book`, `Chapter`, `ChapterVersion`; валідація документів Tiptap; DOCX імпорт/експорт; глобальний пошук; `seed_demo` |
| `apps.boards` | `Board`, `BoardItem`, `BoardConnection`; збереження розкладки |
| `apps.analysis` | Алгоритмічне ядро (`engine/`), `AnalysisJob`, `Finding`, `Evidence`, черга й worker, швидкі перевірки |
| `apps.ai` | `AIService` (доменні операції) + `GeminiBackend` (адаптер), схеми відповідей моделі |
| `apps.language` | Перевірка правопису (Hunspell через spylls), словник користувача |

### Ізоляція даних
Кожен queryset фільтрується за власником (`world__owner=request.user` або `user=request.user`).
Вкладені маршрути (`/worlds/{id}/characters/`) спершу знаходять світ серед світів користувача — чужий світ дає 404.
Посилання між сутностями в тілі запиту (`WorldRelatedField`) приймаються лише з того самого світу; звʼязки між
світами відхиляються ще й на рівні правил аналізу (`cross_world_reference`). Ідентифікатори перевіряються на
діапазон, щоб великі числа не спричиняли помилок БД.

### Час світу
Кожна точка часу: `*_key` (Decimal, порівнюваний у межах світу) + `*_label` (як показувати) + `precision`
(`exact`/`approximate`/`unknown`) + `uncertainty`. Невідомі дати ніколи не вважаються помилкою; приблизні
порівнюються з похибкою (`engine/types.compare_points`).

### Документи розділів
Tiptap/ProseMirror JSON валідується за білим списком вузлів/марок/атрибутів, із лімітами глибини, кількості вузлів і
розміру (`books/documents.py`). Паралельно зберігається `plain_text` (пошук, аналіз, лічильник слів).
Конкурентне редагування — оптимістичне блокування через `revision` (HTTP 409). Версії (`ChapterVersion`) — знімки
не частіше ніж раз на `WW_VERSION_INTERVAL_SECONDS` під час автозбереження, завжди при ручному збереженні,
відновленні й імпорті; зберігається не більше `WW_MAX_VERSIONS_PER_CHAPTER`.

## Алгоритмічне ядро (`apps/analysis/engine/`)

| Модуль | Що робить |
|---|---|
| `types.py` | Знімок світу (`WorldSnapshot`), точки часу, чернетки результатів, fingerprint для дедуплікації |
| `loader.py` | Завантажує знімок із БД (по одному запиту на тип сутності) |
| `graph.py` | Орієнтований граф: суміжність, BFS-шлях, ітеративний DFS-пошук циклу, топологічне сортування Кана, перевірка «чи створить ребро цикл» |
| `rules.py` | Детерміновані правила світу (див. нижче) |
| `mentions.py` | Пошук згадок персонажів з урахуванням відмінювання, псевдонімів, звертань («Доктор») і неоднозначних частин імен |
| `manuscript.py` | Евристики рукопису: загиблий діє, смерть → поява без пояснення, вік, описки в іменах |
| `retrieval.py` | Лексичний пошук релевантного лору для фрагмента (TF-IDF-подібне ранжування, теги, назви, згадані сутності) з бюджетом символів |
| `chunking.py` | Розбиття тексту на фрагменти з перекриттям по межах абзаців/речень |
| `evaluation.py` | Контрольний набір із мітками та обчислення precision / recall / F1 / часу / частки перевірених цитат |

Правила світу: `event_end_before_start`, `death_before_birth`, `status_conflict`, `event_before_birth`,
`event_after_death` (ролі «згадується» / «посмертно» пропускаються), `membership_*` (членство поза життям),
`dependency_cycle` (DFS), `dependency_violated` (топологічне сортування + поширення найранішого допустимого часу
вздовж ланцюжків, у т.ч. через події без дати), `relationship_conflict` (союз і ворожнеча в періоди, що
перетинаються), `relationship_after_death`, `cross_world_reference`, `dangling_reference`, `hierarchy_cycle`
(для підпорядкування/наставництва). Топологічне сортування застосовується лише до графа часових залежностей,
не до графа дружби/ворожнечі.

Категорії результатів: `confirmed` (формально підтверджено, точні дані), `potential` (імовірно з урахуванням
похибки або семантично), `insufficient_data` (у межах похибки, ненадійний оповідач), `unverified`
(припущення моделі, цитату не підтверджено). Рішення автора (`new/accepted/rejected/ignored`) переносяться на
повторні запуски за fingerprint. Результати **ніколи** не змінюють рукопис.

## ШІ (Google Gemini)

* `AIService` — операції `scan_chunk` (перевірка книги), `analyze_plot_holes`, `analyze_character_consistency`,
  `analyze_lore_consistency`, `extract_entities`, `extract_timeline_events`, `explain_finding`. Бізнес-код не
  знає про конкретний API.
* `GeminiBackend` — `POST …/models/{model}:generateContent` з `responseMimeType=application/json` і
  `responseJsonSchema`, `thinkingLevel=low`, послабленими фільтрами безпеки (художній текст із насильством).
  Ключ — лише в заголовку `x-goog-api-key`. Запити розносяться в часі (`GEMINI_MIN_INTERVAL_SECONDS`);
  429 чекає `retryDelay`, 5xx повторюється й переходить на `GEMINI_FALLBACK_MODEL`; вичерпаний денний ліміт →
  `AIUnavailable`. Відповідь, обірвана на `MAX_TOKENS`, рятується до останнього завершеного елемента.
* Безпека промпта: рукопис і лор передаються як огороджені блоки даних з мітками (`[F]`, `[C1]`, `[L2]`…);
  інструкції лише в system prompt. Модель посилається на мітки — справжні id підставляє сервер; невідомі мітки
  відкидаються. Кожна цитата шукається в джерелі (`common/text.find_quote`, толерантно до лапок/апострофів/тире);
  неперевірені результати отримують категорію `unverified`. Відповідь валідується DRF-серіалізаторами;
  невалідний JSON → `ai_error`, база не змінюється.
* Приватність: у логи потрапляють лише id, статуси й типи винятків — не текст. `error_message` завдання ніколи
  не містить тексту рукопису.

### Перевірка всієї книги з памʼяттю сюжету (`analysis/story_scan.py`, `engine/story.py`)

Книга читається по порядку, зазвичай **один запит на розділ** (`AI_SCAN_CHUNK_CHARS`, 40 000 символів). Запит
містить розділ `[F]`, памʼять сюжету `[P…]` — факти з попередніх розділів про людей, згаданих у цьому, — і
довідки з енциклопедії та хронології (`[C…]`, `[E…]`, `[L…]`). Відповідь — `issues` і `facts` разом:

* **Факти** типізовані (`death`, `injury`, `item`, `place`, `knowledge`, `relation`, `time`, `other`) і мають
  дослівну цитату; факт без знайденої цитати не запамʼятовується. `EntityIndex` привʼязує факти до сутностей
  (`c:id`, `f:id`, `p:id`) з урахуванням відмінків, і памʼять для розділу добирається саме за ними.
* **Знахідка** потребує перевіреної цитати з розділу та з джерела, якому вона суперечить (або двох різних цитат
  із розділу); цитата-імʼя («Імʼя: …»), невідома мітка чи низька впевненість — відкидаються.

**Час статусу.** Статус «загинув / зник» має сенс лише відносно часу дії. У персонажа є поле `death_chapter`
(«загинув у розділі…»); `CharacterS.dead_in(chapter)` повертає «так / ні / невідомо» за розділом смерті або
за порівнянням дат (дата смерті й час дії розділу). У довідку для ШІ статус потрапляє лише привʼязаним до
поточного розділу («у цьому розділі: живий, загине пізніше» або «загинув у розділі X»); статус без часу не
передається зовсім. Правило `dead_character_active` так само використовує розділ смерті.

**Перевірка кандидатів у контексті.** Кожен кандидат від першого запиту окремо перевіряє суддя
(`AIService.judge`): він отримує оригінальні абзаци обох місць (±1200 символів, цитата позначена ⟦ ⟧), а не
короткі цитати чи переказ із памʼяті, і обирає вердикт: `contradiction`, `mention_only`, `explained`,
`irony_or_opinion`, `consistent`, `different_entity`, `not_enough_info`. Лишається тільки `contradiction`;
усі вердикти й причини збоїв записуються в `stats` завдання (`judge`, `judged`, `failures`).

**Правила без дублів.** Запуск перевірки за правилами замінює нерозглянуті знахідки правил свого обсягу, а не
додає копії; розглянуті автором лишаються одним записом і переходять у нові результати. Спроба вбивства,
поранення чи «смертельна доза» без явного «помер/загинув/вбитий» не вважаються смертю.

Знахідки зберігаються після кожного розділу. `ChapterScan` зберігає хеш тексту, модель, версію промпта
(`SCAN_PROMPT_VERSION`) і факти розділу. Незмінені розділи повторно не перевіряються, їхні знахідки переходять
у нове завдання. Тому перерване завдання (немає інтернету, вичерпано денний ліміт, закрито сторінку)
продовжується з місця зупинки, а після правок перевіряються лише змінені розділи; `full=true` перевіряє все
заново. Рішення автора щодо знахідок зберігаються і не створюються знову.

## Черга завдань

`AnalysisJob` у БД + процес `manage.py run_worker`:
атомарне захоплення (`UPDATE … WHERE status='pending'`), heartbeat, повторна постановка «завислих» завдань
після перезапуску (до `WORKER_MAX_ATTEMPTS`), не більше `AI_MAX_CONCURRENT_JOBS` (за замовчуванням 1) важких
завдань одночасно, кооперативне скасування між фрагментами, автоматичне скасування застарілих завдань у черзі
при постановці новішого для того самого обʼєкта. Celery/Redis не потрібні.

Режим A (під час письма): фронтенд через 2 с після паузи надсилає 2 абзаци навколо курсора на
`/analysis/quick-check/` (без LLM, попередній запит скасовується `AbortController`).
Режим B (за запитом): завдання `fragment` / `chapter` / `book` / `book_with_lore` у черзі.

## Frontend (`Frontend/src`)

* `api/` — централізований клієнт (`client.ts`: базовий URL з `import.meta.env`, credentials, CSRF, нормалізація
  помилок, `listAll` для пагінації, завантаження файлів) і типізовані сервіси на кожен ресурс.
* `hooks.ts` — `useAsync` (завантаження зі скасуванням застарілих запитів), `useBusy` (захист від повторного відправлення).
* `App.tsx` — сесія, книги користувача, тости, офлайн-банер; маршрутизація через hash (`router.ts`).
* `components/ChapterEditor.tsx` — Tiptap, автозбереження з debounce, ревізії/конфлікти, локальна чернетка в
  `localStorage` на випадок збою, повтор з експоненційною затримкою, версії, правопис, підказки режиму A.
  Редактор вантажиться ліниво (окремий чанк).
