# Worldweaver — план реалізації і статус

## 1. Результати аудиту (стан на початок роботи)

| Що | Стан |
|---|---|
| `Backend/` | порожня папка |
| `Frontend/` | React 19 + TypeScript 6 + Vite 8, без роутер-бібліотеки (hash-router у `src/router.ts`) |
| Дані | усі «книги» захардкоджені в `src/data/projects.ts` (тип `Project`: записи енциклопедії, дошка, події, сторінки) |
| Авторизація | фіктивна: `Auth.tsx` лише записує імʼя/email у state, пароль ігнорується |
| Профіль / налаштування | state + `localStorage`, без збереження на сервері |
| Редактор | відсутній; сторінка «Читати книгу» показує статичні абзаци |
| Дошка ідей | колонки з картками (`Diary.tsx`), без бібліотеки вузлових діаграм |
| Тести фронтенду | інфраструктури немає |
| Git | репозиторій не ініціалізовано |
| `src/Profile.tsx`, `src/Settings.tsx`, `src/Sidebar.tsx` | байт-у-байт копії `pages/…`/`components/…` з неправильними відносними імпортами — через них `tsc -b` падав (21 помилка). Видалено як зламані дублікати (оригінали в `pages/` і `components/` збережено й доопрацьовано). |
| `frontend-dump.txt`, `worldweaver-src.zip` | архівні знімки коду, не використовуються збіркою; не змінювались |
| Середовище | Python 3.12 / 3.14, Node 24, npm 11; PostgreSQL, Docker та Ollama **не встановлені** |

### Відображення понять UI на модель даних

* **Project (UI) = Book + її World.** Маршрут `#/p/<bookId>/<section>`.
* Енциклопедія = персонажі + фракції + записи лору світу (локації, предмети, істоти, інші категорії).
* Щоденник = дошка (`Board`) книги. Хронологія = події світу. «Читати книгу» = розділи з редактором і режимом читання.
* Нова вкладка «Перевірка» — аналіз узгодженості.

## 2. Ключові рішення

Див. [ARCHITECTURE.md](ARCHITECTURE.md): session+CSRF через Vite proxy; PostgreSQL цільова, SQLite для тестів;
типізовані звʼязки через nullable FK + CheckConstraint; час світу як Decimal-ключ + мітка + точність;
Tiptap JSON з білим списком і `revision`; черга в БД + `run_worker`; `AIService` над `OllamaBackend` лише для
loopback; Hunspell uk_UA через spylls.

## 4. Наступні кроки (не реалізовано)

* Перевірити глибокий аналіз з реальною моделлю (`RUN_OLLAMA_TESTS=1`) і підібрати промпти/модель під українські тексти.
* Повнотекстовий пошук PostgreSQL (`SearchVector` + GIN-індекс) замість `icontains`; згодом — векторний пошук.
* Підсвічування знайдених проблем прямо в тексті редактора (зараз — список із переходом до місця).
* Візуальний граф звʼязків і полотно для дошки з довільним розташуванням (API вже зберігає `x/y/width/height`).
* Фронтенд-тести (Vitest + Testing Library) для `api/client.ts` і `ChapterEditor`.
* Розвʼязання займенників і перифразів у текстових евристиках; розширення контрольного набору реальними уривками.
