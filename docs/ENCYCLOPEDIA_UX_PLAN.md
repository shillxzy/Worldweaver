# Енциклопедія як система сторінок — план і рішення

## 1. Поточний стан (аудит, 2026-10-22)

| Що | Як зараз |
|---|---|
| Сторінка `Encyclopedia.tsx` | Плоский список рядків (персонажі + фракції + лор) з вкладками за жорсткими типами (`Персонаж/Фракція/Локація/Предмет/Істота/Лор`) і пошуком у браузері |
| Створення/редагування | Модальні вікна з фіксованими полями: `CharacterForm` (≈20 полів), `FactionForm`, `LoreForm` (`components/EntityForms.tsx`) |
| Ті самі модалки використовують | `Characters.tsx` (картки), `Graph.tsx` («Відкрити картку») |
| Backend | Окремі таблиці `Character`, `Faction`, `LoreEntry` (+ `Tag`) зі структурованими полями; лор — простий текст без форматування |
| Зв'язки | Типізовані `Relationship`, `FactionMembership`, `TimelineEvent` — використовуються графами, хронологією й аналізатором |
| Редактор | Tiptap уже є (розділи книги): автозбереження, ревізії/409, чернетка в `localStorage` |
| Статичні дані | Лише дизайн-константи (`TYPE_META`, `SECTIONS`); усі записи — з backend |

## 2. Проблеми UX

1. Модальне вікно — тісний редактор для довгого тексту; немає URL, на який можна послатися або повернутися.
2. Жорсткі поля нав'язують структуру: «характер», «здібності» тощо видно навіть тим, кому вони не потрібні.
3. Неможливо створити сторінку про щось поза переліком типів («Ціна безсмертя»).
4. Немає ієрархії, внутрішніх посилань, зворотних посилань, форматування в лорі.

## 3. Концепція

**Усе в енциклопедії — сторінка.** Сторінка має назву, необов'язкову іконку й обкладинку, тип (вільний рядок),
вільний Tiptap-текст, необов'язкові властивості, батьківську сторінку та дочірні сторінки.
Тип і шаблон лише задають стартовий вміст і вмикають спеціалізовані панелі.

Структуровані дані, потрібні для аналізу (статус і дати життя персонажа, членство у фракціях, зв'язки, події),
залишаються в наявних таблицях. Сторінка типу «персонаж» / «фракція» / лор-типів **пов'язана** з відповідним
записом (`Page.character`, `Page.faction`, `Page.lore_entry`). Тож графи, хронологія й аналізатор працюють як раніше,
а автор бачить одну сторінку, де текст вільний, а структуровані дані — в компактній панелі.

## 4. Модель даних (backend, застосунок `apps.pages`)

* **`Page`**: `world`, `parent` (self, nullable), `sort_order`, `title`, `icon` (емодзі), `cover` (приватне
  зображення), `page_type` (вільний slug: `note`, `character`, `faction`, `location`, … або власний),
  `aliases` (список інших назв для пошуку й аналізу), `content` (Tiptap JSON, той самий білий список, що й
  у розділах + посилання), `plain_text`, `revision` (оптимістичне блокування), `character` / `faction` /
  `lore_entry` (OneToOne, nullable, не більше одного), `created_at`, `updated_at`.
* **`PageProperty`**: `page`, `label`, `kind` (`text`, `number`, `date`, `checkbox`, `tags`, `page`, `pages`),
  `value` (JSON, валідується за типом; посилання — лише на сторінки того самого світу), `order`.
  Визначення й значення об'єднані: шаблон просто створює стартовий набір властивостей, які автор вільно
  перейменовує, видаляє, переставляє, додає. Окрема таблиця визначень зараз не дає користі.
* **`PageLink`**: `source`, `target` (nullable → «бите посилання»), `target_ref`, `origin` (`content`/`property`).
  Перераховується при кожному збереженні тексту/властивостей. Дає зворотні посилання, биті посилання й основу
  для майбутнього графа знань.
* **`PageTemplate`** (власні шаблони користувача): `owner`, `world` (nullable), `name`, `icon`, `page_type`,
  `content`, `properties` (список `{label, kind}`). Стандартні шаблони описані в коді (`templates.py`).

Посилання в тексті — mark `link` з `href="page:<id>"`; зовнішні — лише `http(s)`/`mailto`. Сервер валідує href.

## 5. Шаблони

Порожня сторінка, Персонаж, Фракція, Локація, Предмет, Істота, Подія, Запис лору + власні (зі сторінки).
Шаблон = стартові заголовки-секції в тексті + стартові властивості + (для персонажа/фракції/лор-типів)
автоматично створений пов'язаний запис. Жодне поле не обов'язкове.

## 6. Навігація (frontend)

* `#/p/<book>/encyclopedia` — домівка енциклопедії: пошук, фільтр за типом, нещодавно відкриті, «Нова сторінка».
* `#/p/<book>/page/<id>` — сторінка в основній області, зліва — дерево сторінок світу.
* Дерево: розгортання/згортання (запам'ятовується), перетягування вузла на інший — зробити дочірнім,
  на «корінь» — на верхній рівень, «+» біля вузла — підсторінка; порядок — меню «Вище/Нижче».
* Хлібні крихти, вкладені сторінки, зворотні посилання, биті посилання — під текстом.
* Редактор: панель форматування + кнопка «+» і команда `/` (заголовки, списки, цитата, роздільник,
  посилання на сторінку). Посилання на сторінку вставляється через пошук наявних сторінок; нова сторінка
  створюється лише явною дією «Створити сторінку …».
* Модальні вікна лишаються тільки для вибору шаблону, підтвердження видалення та вибору сторінки для посилання.

## 7. Надійність

Автозбереження через 1,2 с паузи; `base_revision` → 409 при конфлікті з порівнянням із сервером;
чернетка в `localStorage`; повтор із затримкою при втраті мережі; «Збережено» — лише після відповіді сервера.
Видалення сторінки з дочірніми: сервер відмовляє (409) без явного вибору `children=lift` (підняти на рівень вище)
або `children=delete` (видалити гілку); UI показує кількість сторінок у гілці.

## 8. Підготовка до AI

`plain_text` + `aliases` індексуються пошуком; `GET /books/{id}/chapters/{cid}/relevant-pages/` повертає сторінки,
згадані в розділі (за назвами й іншими назвами, з урахуванням відмінювання — наявний `MentionMatcher`).
Аналізатор бере контекст лору зі сторінок. Важкого аналізу під час збереження немає.

## 9. Етапи

* **A.** Аудит і цей документ.
* **B.** `Page` + API + маршрут сторінки + автозбереження + дерево (вертикальний зріз).
* **C.** Шаблони й властивості, пов'язані записи персонажа/фракції/лору, міграція наявних записів у сторінки.
* **D.** Вкладені сторінки, переміщення, внутрішні й зворотні посилання, биті посилання.
* **E.** Тести, міграції, збірка, перевірка в браузері.

## 10. Ризики та відкриті питання

* **Подвійне джерело даних персонажа.** Текст біографії тепер на сторінці; старі поля `Character.biography` тощо
  переносяться в текст сторінки міграцією, але в таблиці лишаються (не видаляються) і більше не редагуються.
* **Таблиці й зображення в тексті** — поза першою реалізацією (немає розширень Tiptap для них у проєкті;
  зображення сторінок потребують окремого сховища). Обкладинка сторінки — є.
* **Синхронізація назви** сторінки й запису (персонаж/фракція/лор) — односпрямована: зі сторінки в запис.
* **Редактор власних шаблонів** — поки «Зберегти як шаблон» зі сторінки; окремого редактора немає.
* Перетягування в дереві не підтримує точне вставлення між сусідами — порядок змінюється через меню.

Міграція `pages.0002` створила сторінки для всіх наявних персонажів, фракцій і записів лору (текст біографії, опису тощо
перенесено в текст сторінки; короткі поля — у властивості). Вихідні записи не змінено.

Модальні `CharacterForm` / `FactionForm` / `LoreForm` прибрано: редагування відбувається на сторінці. Граф («Відкрити
картку»), картки персонажів, глобальний пошук і докази аналізу ведуть на сторінки.

### Відомі обмеження

* Таблиці та зображення всередині тексту не підтримуються (лише обкладинка сторінки).
* Перетягування в дереві вкладає сторінку в іншу; точне місце серед сусідів — через меню «Вище/Нижче».
* Окремого редактора власних шаблонів немає: шаблон створюється зі сторінки («Зберегти як шаблон»).
* Поля `Character.summary/biography/…` більше не редагуються (текст живе на сторінці); картки персонажів
  показують старе `summary`, якщо воно було.
* Назва синхронізується лише в один бік: сторінка → запис. Перейменування персонажа в графі (через API записів)
  не змінює назву сторінки.
* Посилання на сторінки іншого світу в тексті не блокуються, а позначаються як биті; у властивостях — відхиляються.
